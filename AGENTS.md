# go-trading212

Unofficial Go client for the Trading 212 Public API, generated from the OpenAPI document Trading 212 publishes. If you only want to use the client from an agent, read [.agents/skills/go-trading212/SKILL.md](.agents/skills/go-trading212/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `trading212`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://docs.trading212.com/_bundle/api.yaml` to `api/openapi.yaml` → `scripts/fix-nullable-types.sh` writes `api/openapi.fixed.yaml`, rewriting `type: [number, 'null']` into `type: number` plus `nullable: true` → oapi-codegen with `config.yaml` → `client.gen.go`.

## Stack

- Go 1.26.10.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, the nullable type fix, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The spec says OpenAPI 3.0.1 but uses 3.1 nullable type lists, which oapi-codegen rejects. Skip `fix-nullable-types.sh` and generation fails.
- Without the `number` to `float64` mapping in `config.yaml`, prices and amounts become `float32`.
- Method names are the spec's operation IDs: `GetAll`, `Create`, `Update`, `Delete` are pies, `Orders1` is order history, `PlaceStopOrder1` is a stop order and `PlaceStopOrder` a stop-limit order. A spec change that renames an operation ID renames the method.
- `make generate` always downloads the current spec, so it can change the client even when nothing here changed. Review the generated diff before committing it.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
